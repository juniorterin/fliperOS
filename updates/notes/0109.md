- **First to (FT) on the versus scoreboard.** In a game with a scoreboard, pick first to 1 to 10 and the two players' names: the names take the place of the characters on the LED marquee, with "FT3" in the middle, and the first player to win that many matches gets their name in their colour, a blinking WIN! and fireworks in the corners. Then a new set starts from 0 x 0. A game opened in first to starts on the scoreboard instead of its art, and a name too long for its half scrolls round. It also shows in the web panel's preview and on the OBS marquee page.
- **PLAY FT on the game page of the web panel.** Next to PLAY, in games with a scoreboard: a window asks for the first to and the names, and the game opens in first to for that match only. Everything is cleared when the game closes. In a game without a scoreboard the button is dimmed and explains why, pointing to the version of the same game that has one. A new **Version** picker under PLAY lists the original and its clones in the folder, marking the ones with a scoreboard.
- **Marquee card (formerly Marquee preview).** Art, Scoreboard or FT: FT shows the first to and the names, with **Save** and **Reset score** (back to 0 x 0 in the game that is open).
- **ZeDMD: "Now Playing" and the high scores no longer stutter.** The scrolling text changed about 600 pixels per frame, more than the panel's USB link keeps up with, so it fell behind and skipped frames. Now the text goes in still pages (Now Playing, the game's name, one high score per page) swapped by the same sweep as the system change. A long game name without art alternates pages the same way.
- **ZeDMD: the 3D logo no longer shows up in the middle of a game.** When the panel's service restarted during a game (an update being applied, for example), it played the logo animation until the game closed. Now it shows the game's marquee again.
- **MAME games opened from the FliperOS frontend go through the launcher again.** They skipped it, so the marquee stayed on the system name (Arcade) for the whole game, and the game had no log, no game outputs, no cloud backup and no versus scoreboard. The RetroArch net play of the frontend also built a wrong command.
- **HBMAME no longer crashes half the times it opens a game.** The MAME controller file gave player 4 keypad keys under names MAME does not know (KEYCODE_8_PAD instead of 8PAD), and a wired controller that is unplugged as joystick 95. MAME dropped them, the port was left empty, and HBMAME crashed when opening CPS2 games such as X-Men, Street Fighter Alpha 3 and Super Street Fighter II. This update writes the file again with the right names.
