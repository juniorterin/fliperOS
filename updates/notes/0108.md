- **A Batocera disk is used where its games really are.** A disk that Batocera set up keeps everything in the root of its `SHARE` partition (`roms`, `bios`, `saves`...). When the disk also had a `batocera` folder (an old copy of the empty folders, with one sample game per console), FliperOS took that one only because it came first: the frontends listed almost no games, and `~/bios` and `~/save` pointed to empty folders. It also refused the real `roms` folder once FliperOS had written its own folders into it (after `~/roms` was pointed at it). Now every folder that looks like Batocera is compared and the one with the most games wins; a `roms` folder with the FliperOS folders written in it still counts.
- **A disk set up on the wrong folder is fixed by this update.** The consoles move to the right folder keeping the core you chose, and `~/bios`, `~/save` and the other shortcuts follow. Nothing is moved or deleted on the disk, and a shortcut you made yourself to another place is left as it was. The same check runs every time the cabinet starts or the disk is plugged in, and by hand with `fliperos-setup --batocera repair /media/fliperos/NAME`.
- **ZeDMD and the marquee: the system change is a sweep that keeps up with the panel.** The ZeDMD USB link takes about 10 ms per frame, and the side slide of the logo moved the whole logo every frame, so the panel ran 1.2 s behind and the animation reached about 5 frames per second. Now a line sweeps the panel and leaves the new logo behind it (each pixel changes once, in about 0.4 s), and each frame lasts what the panel takes to receive it, with no flashes. The end of a sweep no longer gets stuck (the logo used to stop cut off until the next event): the last frame is repeated a few times and the connection is held until the next event connects. The frontend sends the marquee the tile under the cursor of the system strip without waiting for the list to switch, and in the FliperOS menu the RetroAchievements item no longer silences the marquee when the cursor moves, and has its own animation (a gold cup and CHEEVOS).
- **16:9 crop in custom games: the game sees the whole 1280x720.** The crop made the X server tell the game that the monitor was only the 960x720 that the tube shows, so a widescreen game opened in a 4:3 window with black bars above and below. Now the game sees a 1280x720 screen and fills the height, and the tube shows the middle of it. Wine games, PortProton included, read the size from a Wine setting, so the launcher writes `UseXRandR=N` in the game's prefix while the crop is on and takes it out when it is off. Tried with a test window and Wine 9 on a cabinet, not yet with a game on the tube.
